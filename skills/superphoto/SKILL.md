# SuperPhoto

SuperPhoto 在本机用 Lightroom 修图。这个技能只调用已经在运行的 SuperPhoto，不要自己启动第二个进程，也不要打开它的窗口去点。

命令是这个 skill 里 `scripts/superphoto-agent.sh` 的绝对路径。一条命令只做一件事。不要用 `~`、shell 变量、`;`、`&&` 或换行把几条拼在一起。

进度在命令的标准错误里（`step: …`）。标准输出是一份 JSON。`ok` 为 false 时，把 `error` 用一句人话说给用户，不要自己重跑。

## 修一张图

用户附来照片并说要修、要调色或要后期时：

1. 先看服务在不在：`sh <脚本绝对路径> status`
   - `running` 不是 true：告诉用户先打开 SuperPhoto，不要改用别的修图办法。
   - Lightroom 还没连上时可以继续。修图过程会自己去连；失败时 JSON 里会写原因。
2. 用用户这张照片在这台机器上的绝对路径：`sh <脚本绝对路径> edit <照片绝对路径>`
   - 这一步会等好几分钟。不要同时再交另一张。
   - 超时或中途断开时，JSON 里有 `job_id`。稍后用 `sh <脚本绝对路径> job <job_id>` 再取，不要重新 `edit`。
3. 对 `variants` 里的每一张，用 Read 读 `path`。这样照片会出现在对话里。不要读配方、审计或 JSON 文件。
4. 回复时只说每张的槽位、标题和一句原因，并问想留哪张、想改哪里。有 `note` 就说明哪几张没交出来。不要贴滑块、路径以外的内部文件名，也不要替用户选一张，除非用户说「直接给我一张」——那时先讲自然精修那张，并补一句其他张也在上面。

## 用户看完之后

先分清两件事。评价不改当前这张；微调才会重渲。

- 「用 A」「这张好」「喜欢这种」：`sh <脚本绝对路径> rate <job_id> <槽位> like`
  没被提到的槽位不要标成不喜欢。回复里说明这只记住偏好，这一张没有变。
- 「不喜欢这种冷调」「这种不要」：`sh <脚本绝对路径> rate <job_id> <槽位> dislike`
  同样说明只影响以后相似的照片。用户要是还想改这一张，再按下面微调。
- 用户撤销评价：`sh <脚本绝对路径> rate <job_id> <槽位> clear`
- 「亮一点」「主体亮一点，背景暗一点」「颜色太重」：这是要改这一张。
  `sh <脚本绝对路径> refine <job_id> <槽位> <用户的原话>`
  用户没说是哪一张时，先问槽位，不要自己猜。
  这一张已经微调过、用户是在新版本上继续说的，加上 `--parent <上次的 refinement_id>`。
  完成后用 Read 读返回的 `path`，用 `summary` 说改了什么。失败时原来的成片还在，照 `error` 说明。

「太暗」「太亮」「颜色不对」要走微调，不要只打评价。评价不会重渲。

一次只处理一条修图或微调。上一条还在 `running` 时，告诉用户正在修，不要再交一张。
