# resources 素材整理与流程接入（2026-11-13）

这次将用户提供的本地资料整理为可追溯、按场景使用的修图原则，并接入现有预设选择、方案规划和成片复核。没有训练模型，没有把商业预设批量复制进应用，也没有将教程中未支持的操作记作已实现。

## 实际覆盖

目录共 128 个文件，625,611,710 字节：34 个 DNG、26 个 ZIP、24 个 JPG、23 个独立 XMP、16 个 MP4、5 个 PNG。

- 解析独立 XMP 和 ZIP 内 XMP 共 401 条，按文件字节去重为 379 条，重复 22 条。
- 数字字段与曲线结构签名为 341 种。这是结构统计，不是 341 种已转换、可执行或视觉独立的风格。
- 去重后的用途：完整外观 298、说明 15、基础 9、清除 2、颜色分级 32、颗粒 7、蒙版 16。含局部结构的“基础”条目优先计入蒙版。
- 16 段视频约 107 分钟，按约 15 秒间隔抽取 432 帧，使用 Windows.Media.Ocr 进行本地中文 OCR，并人工复核相关关键帧及联系表。没有音频转写，没有声称逐句观看或完整理解全部视频。
- 63 个 JPG/PNG/DNG 文件中成功解码 50 个（含说明图与拼贴），13 个 DNG 在 rawpy/LibRaw 下报 `LibRawFileUnsupportedError`。失败文件集中在沙漠、KIRINOMA、Tim Northey 和品川力的部分示例；不把它们算作已分析照片。完整列表见本地 `photos.json`。

原始预设数值只保存在指定的本地库存报告中。应用知识包保留文件路径、字节数、SHA256、视频时间点和人工整理的原则；运行时不依赖原素材目录。

## 提炼出的原则

| 原则 | 对流程的作用 |
|---|---|
| 基础明暗与色感分层 | 当前照片的曝光恢复独立计算，各候选不继承示范照片的曝光、白平衡与降噪。 |
| 影调与色调分别判断 | 先组织暗部、中间调、亮部，再检查颜色；不追求均匀直方图。 |
| 去灰与保留空气透视 | 明确雾景且需要保留空气感时，限制全局去雾、清晰度和反差，以及天空/背景的去雾与清晰度。 |
| 植物主色与暖色重点 | 绿色整理要检查叶片光泽，以及天空、水体共享色相造成的连带影响。 |
| 明亮肤色与材质分开 | 限制人像全局和 subject 的过强纹理/清晰度；不把 subject 宣称为皮肤专用蒙版。 |
| 夜景灯光层次 | 保留夜色密度、灯光颜色和过渡，检查减色是否破坏灯牌、水面或天空。 |
| 柔灰哑光骨架 | 小幅抬黑、柔化肩部，同时保留中间调密度；不以全局变灰替代设计。 |
| 雪景白色与阴影 | 明确雪景且要求自然色时，限制风格曲线对上部影调的过度压暗，保留独立的 RAW 恢复。 |
| 暮色与拍摄依赖 | 后期调整已有光色，不承诺生成光束、换天空或还原拍摄光晕。 |
| 颗粒与技术细节独立 | 不从风格预设批量继承强降噪、锐化或虚构的胶片光晕。 |
| 局部目标必须可执行 | 只使用实际支持并有依据的 subject/sky/background；不移植作者底片的画笔、渐变与坐标。 |

详细来源在 `src/superphoto/resource_lessons.json`。视频证据使用原文件 SHA256 和时间范围；XMP 证据记录源文件或 ZIP 内成员、字节哈希与结构用途。运行阈值与三套新配方是自行设计的保守工程解释，不是教程逐字数值或原作者配方。

教程中临时切换黑白用于观察影调，不会触发最终黑白输出。KIRINOMA 教程中明确标识的 AI 创意参考，不作为真实相机底片的前后训练对。

## 生产接入

1. `resource_materials.py` 和 `scripts/study_resources.py` 负责离线盘点。ZIP 内只读取有界 XMP，不解压、不执行；拒绝不安全路径、实体声明与超限输入，坏 ZIP 会单独记录。
2. `resource_knowledge.py` 加载随应用分发的小型知识包，根据已诊断的主体与场景筛选原则。
3. `style_selection.py` 注册三个自主配方：`resource_matte`（柔灰哑光）、`resource_snow`（雪景清透）、`resource_night`（夜色光序）。它们经过场景准入、评分与差异选择，不强占 A/B/C 位置，反馈仍绑定稳定的实际风格 ID。
4. `finishing_context` 将适用原则和来源交给方案规划；模型对选中预设做稀疏适配。缺省控制继承，显式零值可以关闭控制。
5. `bound_direction` 在现有 RAW/JPEG 和逐图研究保护后，应用雾气、人像材质和雪景曲线保护。每项实际限制记录原则 ID、控制、调整前后值；原配方不被原地修改。
6. `pipeline.py` 为每个任务写入 `resource-guidance.json`，并把适用原则 ID 与最多四个检查点保存到编辑意图中。规划审计保留知识上下文、来源和实际参数限制。
7. `review.py` 把这些检查点作为条件化参考，要求以原片与输出像素为准，不把资料描述当作当前照片事实。原有独立损坏复核继续生效。

风格匹配的数值证据与来源分开保存：`StyleMatch.evidence` 保持数字字典，`resource_lesson_ids` 保存原则标识。

新风格的准入需要场景支持。白墙、亮天空不能仅因白色面积大被视作雪景；背景出现远山积雪不把建筑主体变成雪景；低亮度日光照片不会仅凭亮度获得新夜景配方。默认“保留空气感”本身也不能证明照片有雾。

本地技术诊断不能可靠识别所有语义对象。未提供明确场景时，雪景、雾气等特定原则不会自动启用；配置可用视觉模型后，使用其主体描述和题材诊断。规则可在无模型时运行，但不会凭空补齐视觉理解。

