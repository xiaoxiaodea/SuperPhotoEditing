# 修图风格流程优化

日期：2026-11-14。目标是修正生成流程中基础校正覆盖风格、重试无效的问题，而非为单张照片硬编码三组滤镜。

## 流程变更

1. **校正曲线与风格曲线组合。** 过曝 JPEG 使用保留白端的基础曲线时，规划阶段计算 `style(base(x))`，包括风格锚点在基础曲线中的原像，避免漏掉转折。`Recipe.merged` 的通用曲线覆盖语义不变，只有明确的技术校正组合使用专门函数。
2. **保护最终范围，不再把所有方案换成同一条曲线。** 校正曲线附近允许有限的风格密度变化，保留预设通道曲线、HSL 明度、对比度、阴影与黑位。RGB 单调性及白端继续受约束，通道曲线仅在白端归白。保护函数幂等，不会因重复验证再次叠加基础曝光。
3. **限定冲突控制。** 大面积已裁切 JPEG 白区的负曝光、高光、白色色阶和参数曲线高光段会使白平台在 RGB 曲线前变灰，因此由技术校正层统一负责；保留其它风格控制。实际导出继续检查过曝未改善、纯白压灰、新裁切、过暗和过饱和等问题，没有降低这些质量门槛。
4. **减弱风格时回到已校正基础。** 按比例混合完整曲线与基础曲线，禁止向未编辑的 identity 曲线回退而丢失曝光校正。预览重试和实际预设减弱使用同一逻辑。
5. **选择和重试比较真正执行的设计。** 预设选择阶段使用合并校正、场景保护后的参数签名。曝光恢复任务的影调重试相对于已校正基础判断风格密度，并让其变化通过保护层，避免每次改动又被覆盖。
6. **相似候选改选方向。** 一次原方向调整仍过于相似时，从本次已保存的候选排名中选择未使用预设。再次检查场景准入，保留排名中的反馈权重，比较与已交付方案的设计差异。雪景、夜景、人像等准入不能被多样性需求越过。
7. **匹配真实交付身份。** 新预设只有在画质及候选选择通过后才成为交付方案，文件、配方、标题、预设 ID、风格强度和反馈身份同步更新。被拒的替换不能改变保留方案的身份。原片和旧任务不改动。
8. **如实表达不足。** 如果有质量合格但相似的成片，保留第一个有效设计供比较。审计与 API 增加 `distinct_delivered`、`similar_slots`；页面明确显示哪些方案接近，不用“交付三张”冒充“三个独立方向”。

主要实现：`exposure.py`、`candidate_design.py`、`preference.py`、`qa.py`、`style_selection.py`、`lightroom_qa.py`、`pipeline.py`；页面仅增加接近方案的提示。
