# 自然颜色复核与偏色修正

日期：2026-11-14。本轮继续使用本机照片与官方 Windows LightCraft v0.21.1。原片只读，照片未上传，旧任务与数据库保留。所有实际跑片均经 CLI 完整流程，任务顺序执行。

## 本轮解决的问题

上一轮逐片复核发现，部分技术检查通过的方案将白冰、白衣或白地染成青绿色。全局平均饱和度并不高，原有绿色、暖色、蓝色区域检查也没有证明这些近中性位置发生了颜色损伤。候选差异统计还可能把这种偏色计作成功的方向差异。

对上一轮实际导出按固定基线位置测量，冰川 C、湖边人物 C、白地 B 的近中性亮部新增色度偏移明显。这些只是像素测量，不代表本地系统识别了冰、衣物或地面。

## 实现

### 结合编辑意图检查真实像素

`assess_lightroom_render` 新增 `natural_color` 参数，默认关闭以保持独立调用兼容；主出片流程的最终检查、替代方案检查和实验性精修检查均传入实际 `EditIntent.natural_color`。原来的各阶段损伤检查继续执行，不把某个中间阶段当成最终曝光或颜色目标。

仅当要求保留自然颜色时，从未编辑 LightCraft 基线选取 `55 < L* < 98`、`C* < 6` 的近中性亮部，固定其坐标后测量成片。区域少于整幅 0.5% 时，不据此启动全局颜色修正。每像素 Lab 的 a/b 变化先分别取中位数，再取该变化向量的长度；它不是逐像素距离中位数。偏移大于 3，且输出颜色到“原片颜色—中性灰”线段的逐像素距离中位数大于 2.5 时，报告 `neutral_color_cast` 并拒绝当前导出。后一个条件允许朝中性灰去色，但不能让总色度相近的冷蓝转绿绕过检查。

审计新增 `neutral_assessment`，记录面积、偏移、前后色度及 a/b 变化。规则不把原片暖色灯光、蓝天或有色物体一律中和；显式创意配色 `natural_color=false` 不触发该检查。它仍是有限的像素保护，不是摄影意图或材质识别。

### 保留明暗设计，只减弱造成偏色的控制

`reduce_color_cast` 生成从原片重新执行的完整配方，保留当前方案实际生效的曝光、RGB 总曲线、对比、亮暗滑块、HSL 明度、色轮明度、局部曝光以及细节、裁切等控制。

独立 R/G/B 通道曲线向它们共同的加权密度靠近，同时保留基础校正的通道差异。相对白平衡、饱和度、HSL 色相/饱和度、分级色轮和蒙版内的颜色控制向基础校正减弱。曲线在原锚点并集上计算，超出执行器预算时最多使用 32 点，并保持单调。它保留的是通道的加权显示密度，不声称严格逐像素保持物理亮度；最终导出仍须重新通过完整损伤与曝光检查。

首轮仅偏色失败时，直接结束增量叠加，在新原片副本上按 50%、25%、12.5% 的颜色强度尝试修正，最多使用已有的三次替换预算。审计以 `neutral-color-repair` 和 `color_style_weight` 标明。修正从阶段回退后的有效配方生成，不重新引入已撤销的曲线。

若同时存在过暗、裁切等其他硬损伤，先走原有技术修正；其他损伤解决后再做颜色修正。颜色变自然不能成为忽略明暗损伤的理由。新检查不会修改用户指定的二次微调意图；那条路径仍按用户要求保留已有风格。

### 候选选择的边界

保留原有策略：必须先通过技术检查与视觉损伤检查，再比较方案差异。后续版本仅有更高的 Lab 距离或更高的通过分数，不足以证明更好看；仍没有合适独立方向时，保留首个有效设计并标记接近。本轮没有为了增加独立方向数而放宽质量门，也没有将固定曝光/染色强度加入所有照片。

## 保留的局限

- 原片没有足够近中性亮部时，这个保护不介入；不能据此证明整幅配色正确。
- 轻度冷青倾向、近中性区域以外的颜色错误、局部相反偏色互相抵消等情况仍可能漏检。
- 固定位置比较依赖前后构图一致。最终检查传入实际有效配方；发现非默认裁切、旋转、手工畸变或透视变化时，跳过此项检查并在 `neutral_assessment.skipped` 记录 `geometry_changes`。镜头配置本身没有独立像素对齐验证；其他损伤检查继续执行。
- 三次替代预算共享于画质修复、颜色修正和差异搜索，不保证能修复任意失败替代方案。
- 小人物的语义局部精修、天空斑点修复、云端视觉 API 与 NAS 验证仍未在本轮实现。
