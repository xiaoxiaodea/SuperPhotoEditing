# 按画面选择并执行预设：2026-09-26

用户反馈的固定化有实际代码原因：旧 pipeline 先按题材分配少数 finishing methods，再选 look；build_plans 遇到 direction 后直接使用 method recipe，跳过已选 XMP/builtin 配方。无反馈时常是 natural/sculpted/soft_warm；look ID 与实际调整不一致。另外，XMP 的 SplitToning/ColorGrade 曾转换成旧 RGB grade，而原生 Lightroom 通路只写 color_grading，分区染色没有执行。

## 当前行为

- 在方案设计之前统一匹配 28 个可执行风格（16 个导入 XMP、5 个基础风格、7 个研究配方）。faithful 与 rescue 不再占固定槽位。68 个由参考成片统计推导的 HB 配方不作为作者原版预设参与自动竞争；逐图研究继续给方案设计提供参考。
- 主体语义和使用条件先排除明显冲突；光线、颜色、练习图距离、读图建议和相似场景的明确满意度反馈共同排名。统计色块不当作肤色或水体的语义证明，随机 job ID 不再决定风格。
- 在兼容候选中比较风格家族和受保护后的曲线、HSL、原生色轮等参数差异。没有固定的 A 自然、B 冷、C 暖角色。
- 每个方向从选中预设的真实配方出发；模型返回按图调整的稀疏覆盖。缺省参数保留，显式零仍可取消不合适的色彩变化。模型不可用时保留同一选中预设，而不返回旧三件套。
- 原生 XMP 色轮直接导入，保留显式零、亮度、混合与平衡。旧 RGB grade 仅作有上限的方向近似转换，已有原生值优先，转换幂等，不重复叠加。
- 三槽采用相同的风格质量规则。失败时减弱自己的风格增量，保留共享技术恢复与蒙版，不借用另一槽的曲线。原始基线回退清除实际预设身份，避免把满意度记到未交付的预设。
- 每张保存真实 preset ID、起始强度、选择依据、起始配方、模型调整和 Lightroom 有效配方；应用的“为什么这样调整”展示选择依据。

报告：`.analysis/scene-presets-2026-09-26/index.html`。三张既有输入均复制到独立目录，重新读图和设计方案，并真实经过 Lightroom 分阶段导出，未使用生成式改图。

| --- | --- |
| 日光人像 | 日系胶片、韩系、SKAM 北欧 |
| 湖边白建筑 | 唐顿庄园、风光层次、杂志硬朗 |

九张输出均与对应 Lightroom 最终导出字节一致，并通过当前像素 QA；原文件及输入副本 SHA-256 一致。三组方向均由模型返回，没有方向回退。最终代码重新选择并组合配方，与本轮原生导出的计划一致。对六张已有读图记录另做了选择回放，记录在 `six-scene-selection.json`。

本轮实图检查关闭视觉复核和为拉大候选差异而进行的重试，保留逐阶段像素检查；目的是隔离验证预设从选择到执行的通路。应用默认设置未因验证而关闭这些选项，实验性 finishing review 仍默认关闭。技术合格不等于审美优胜，示例并不证明已达到大师成片水平。

415 项测试通过；新增覆盖包括语义冲突不能被模型或历史点赞越过、不同场景的选择、XMP 稀疏适配到原生控制、预设与方向身份错配拒绝、相似场景反馈、三槽一致修复策略，以及 RAW 天空恢复不随风格回退衰减。安装记录与导出核验保存在 `verification.json`。
