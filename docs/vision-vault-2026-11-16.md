# 视觉模型保险箱（2026-11-16）

## 用法

1. 打开客户端（`uv run superphoto app`），点顶栏「视觉模型」。
2. 第一次使用时设置保险箱口令，至少 10 个字符。口令无法找回，忘记后只能清空全部配置重新开始。
3. 点「添加模型」，只需选择服务商并粘贴 API Key，然后点「保存」。本机 Ollama 和本机 OpenAI 兼容服务不需要 Key；「其他 OpenAI 兼容服务」还要填写服务地址。
   - 保存时，客户端用这个 Key 获取服务商的模型列表，排除向量、语音、画图等不能看图的模型，再按服务商的推荐顺序选出前 3 个，逐个发送一张 64×64 的纯色测试图。第一个说对颜色的模型会被保存。
   - 如果没有模型能看图，配置不会保存，界面会说明原因，例如 Key 无效、余额不足，或者这个服务商的模型不接受图片。Key 无效、权限不足、限流或连不上服务地址时，会立即停止尝试。
   - 想指定模型、更换服务地址（例如代理），或修改接口协议时，展开「高级设置」填写。模型名留空表示自动选择；编辑时清空模型名，会重新自动选择。
   - 内置的服务商有：OpenAI、xAI Grok、Google Gemini、Anthropic Claude、DeepSeek、阿里云百炼、火山方舟、智谱、Kimi、硅基流动、腾讯混元、阶跃星辰、百度千帆、Mistral、OpenRouter、Ollama、本机 OpenAI 兼容服务和其他 OpenAI 兼容服务（`src/superphoto/vision_presets.py`）。
   - DeepSeek：如果它当前的 API 模型不接受图片输入（据目前所知，deepseek-chat 和 deepseek-reasoner 都只能处理文字），保存时会提示「可能不支持图片输入」，配置不会保存。这种情况下，可以通过硅基流动等平台使用 DeepSeek-VL 系列模型。
4. 点「测试」：客户端会再发送一次同样的测试图，显示是否连通、耗时，以及模型能否看懂图片。
5. 可以添加多个模型（最多 12 个），用 ↑ ↓ 调整顺序。处理照片时按列表顺序使用模型，前一个失败时自动换下一个。保险箱里的模型都失败后，再依次尝试 `.env` 里的配置（Ollama → OpenAI 兼容 → xAI）和本地规则。
6. 客户端每次启动后，保险箱都处于锁定状态，需要输入口令解锁，模型才能使用。点「锁定」会立即清除内存中的配置。

## 保护了什么

| 内容 | 存放位置 | 谁能看到 |
|---|---|---|
| API Key | 加密文件 + 解锁后的客户端进程内存 | 没有任何人：保存后只写不读，管理界面也只显示「Key 已保存」 |
| 服务地址、模型名、备注 | 同上 | 只有在当前客户端窗口输入过口令的人 |
| 「视觉模型 1、2…」编号、启用数量、是否解锁 | — | 所有人（健康检查、任务记录、日志、命令行） |

- **加密**：`data/vision-vault.json` 用 AES-256-GCM 加密，密钥由口令经 scrypt（N=2¹⁶，约 64 MB 内存）派生。口令本身不会写入任何地方。每次保存都换新的随机数，并通过临时文件原子替换。
- **审计脱敏**：保险箱里的模型在任务记录、`plan.json`、`critique.json`、错误信息和健康检查中都只记为 `provider: "vault"` 和 `model: "视觉模型 N"`。不记录服务商返回的模型名和接口协议，只保留 token 用量。模型回答中如果出现 Key、服务地址、主机名或模型名，会替换为 `[REDACTED]`。`httpx` 和 `openai` 的请求日志级别固定为 WARNING，因此不会打印请求地址。
- **防止把 Key 发到别处**：修改服务地址或类型时，必须重新填写 Key，已保存的 Key 不会跟随到新地址。远程地址必须使用 https，http 只允许本机和局域网地址。
- **管理权限**：输入口令后，客户端会获得一个 2 小时的 HttpOnly、SameSite=Strict 会话 Cookie，只作用于 `/api/vision` 路径。锁定或服务重启后，Cookie 立即失效。写操作只接受同源的 JSON 请求，接口不会回显请求内容。连续输错口令时，接口会逐步延迟响应。
- **命令行**：`superphoto process`、`vision-check` 等命令在客户端以外的进程中运行，无法使用保险箱里的模型，只能使用 `.env` 或 Ollama。

## 限制（如实说明）

- 保险箱可以防止有人从文件、日志、任务记录或接口中读到配置，但无法防御一个以你的 Windows 账户身份运行、并且刻意攻击的程序。这样的程序可以读取已解锁客户端的进程内存，也可以修改本项目的源代码，在你下次输入时截获。Claude 在这个项目里有写代码的权限，因此真正的保障还需要你自己审阅改动。
- `.env` 是明文。不要再把 Key 写进 `.env`；本机 `.env` 里现有的 `XAI_API_KEY=` 是空的。
- 口令的强度决定了离线猜测的难度。建议使用 4 个以上随机词组成的短语。
- 未解锁时提交的照片会退回 `.env` 或本地规则诊断。界面顶栏的状态会提示「保险箱已锁定」。

## 涉及文件

- `src/superphoto/vault.py`：加密、解密、配置清洗（含服务商预设）、只读编号视图。`draft_profile` / `commit_profile` 把校验和保存分成两步，自动选模型就在这两步之间进行。
- `src/superphoto/vision_presets.py`：服务商列表（地址、协议、模型偏好），以及模型排序函数 `rank_models`。
- `src/superphoto/vault_routes.py`：客户端接口 `/api/vision/*`。新增 `GET /api/vision/presets`，只返回服务商名称和地址，不返回模型偏好。保存时如果没有填写模型名，会自动选择模型；失败原因只根据错误类型和 HTTP 状态码生成，不会回显服务商返回的内容。
- `src/superphoto/vision.py`：`auto` 模式先按顺序尝试保险箱里的配置，并对审计脱敏。测试函数 `test_profile` 和自动选模型函数 `discover_model` 使用同一个测试图检查 `_check_profile`，只返回连通情况、耗时和状态码。
- `web/`：「视觉模型」对话框。
- `tests/test_vault.py`：密文不含明文、口令错误、换地址或换服务商必须重填 Key、审计和接口不泄露、跨站请求被拒、锁定和重置；只填服务商和 Key 能自动选出看图模型；没有看图模型时不保存；Key 无效时立即停止；能识别旧配置所属的服务商。`tests/conftest.py` 让测试不会读到真实的保险箱。
