# 多套方案与本地经验（2026-11-23）

## 为什么改

- 原流程每张照片固定出 A / B / C 三套（自然、戏剧光影、风格化色彩），每套都要逐版复核，最多再修订两轮。
- ref-r12 / r13 共 117 次复核的结果：
  - 复核分数与「离摄影师成片的距离」几乎不相关（相关系数 −0.01）；
  - 没有一次复核否决过渲染；
  - 每次复核约 93 秒，提示词约 4.4 万字符。
- 结论：逐版复核既慢又费 token，也选不出好图。
- 题材和审美因人而异，所以改为：
  1. 每张照片多出几套方向不同的方案；
  2. 用户 pass 掉不喜欢的，留下喜欢的，标出最爱；
  3. 系统按这些选择学习用户在类似画面上的偏好。

## 流程（`directed.run_directed_job`）

1. **读元素**（`read_elements`）
   - 一次简短的视觉请求，发送一张 768px 预览。
   - 返回画面元素、光线类型和题材，都用 `experience.py` 里的固定词表，例如天空、雪、沙丘、人物、倒影；逆光、蓝调时刻、阴天。
   - 词表固定，才能拿这张的「雪」和下一张的「雪」做比较。
   - 请求失败不影响出片，只是本次找不到相似经验。
2. **取经验**（`experience.py`）
   - 用元素、光线、题材、来源和曝光特征，在本地评分里找相似画面。
   - 整理成三类参考，交给规划提示词：
     - 每个方向在相似画面上被选为最爱、留下、pass 的次数；
     - 用户口味：留下 / 最爱的版本相对同一张 A 的偏移，例如中间调更亮、黑位更灰、更暖；
     - 最相似画面上的最爱方案。
3. **选方向并写方案**（`plan_versions`，`library` 参数不为空时）
   - A 固定为自然完成。
   - 其余每套，由模型从方向库中按本图元素选一个方向，并写明理由。方向库包括：
     - 戏剧光影、通透明亮、风格化色彩；
     - 每个参考 look 各一个配色方向；
     - 以前为其他照片提出的新方向。
   - 也可以提出新方向（`"id": "new"`，带中文标题和角色说明）。新方向以标题的哈希为稳定 id 存入 `directions` 表，之后照片上的评价会累加到同一个方向。
   - 选择规则：
     - 同一方向只用一次，最多两套基于 look；
     - 无效、重复或缺失的选择，按方案内容回退到未用过的方向，并写入备注。
4. **渲染**
   - 与原流程相同：求解器试渲染、`safety_gate`、与 A 太接近时重新规划一次（`_apart_fix`）。
   - 同时最多 3 个渲染（`RENDER_WORKERS`）。
5. **一次损坏检查**（`damage_check`，`directed_max_revisions = 0` 时）
   - 一次请求发送原图和全部版本，每张 1024px，只问损坏：光晕、蒙版边缘、断层、色斑、溢出、肤色、瑕疵。风格不同不算损坏。
   - 严重度 ≥ 0.65 的版本撤下，较轻的问题写进说明。
   - 检查失败时照常交付，并注明「损坏检查不可用」。
6. **交付**
   - sidecar 的 `style_workflow.method_id = "direction:<id>"`，`direction_title` 为方向名。
   - `experience` 块包括：
     - 画面档案（`profile`）；
     - 方向和理由；
     - 成片实测的黑位、中间调、白位、色彩量和冷暖；
     - 本图上的学习权重 `weight` 和展示名次 `rank`。
   - 结果页按 `rank` 排列，学到的偏好越高越靠前，同分时 A 在前。数字键按展示顺序切换。

## 学习（`experience.py`）

- **评价取值**：最爱 2、留下 1、pass −0.5。pass 只说明这种处理不适合那张图，权重低，而且只在相似画面上起作用，不是禁用。
- **方向权重**：exp(clamp(0.6 × Σ 相似度 × 评价取值, ±1.5))。没有相似评价时为 1。
- **相似度**：
  - 由共有元素（Jaccard）、光线、题材、来源和曝光特征综合计算；
  - 低于 0.2 的记为 0；
  - 没有共同元素且题材不同时直接为 0。
- **存储**：全部在本机 `data/superphoto.db`。评价在 `ratings` 表，方向在 `directions` 表，画面档案和成片实测在各版本的 sidecar 里。不上传任何内容。

## 配置

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `SUPERPHOTO_DIRECTED_VERSIONS` | 6 | 每张照片的方案数，3–9。3 为固定的三套方案，与基准测试一致 |
| `SUPERPHOTO_DIRECTED_MAX_REVISIONS` | 0 | 每套的复核修订轮数。0 表示改用一次合并的损坏检查 |

三套模式（3）同样会读元素、记录方向（`direction:natural` / `dramatic` / `palette` 或 `look:<id>`），所以在三套模式下的评价也能学习。

## 验证

`tests/test_directed.py` 新增 4 项：

- 6 套方案的端到端流程：读元素 → 选方向 → 新方向入库 → 一次损坏检查撤下严重损坏 → sidecar 记录；
- 相似照片上的评价进入下一张的规划提示词，并决定排序；
- 方向回退与不重复；
- 损坏检查不可用时照常交付。

`tests/test_experience.py` 覆盖评分表迁移、词表、相似度、权重、口味和范例。

## 尚未验证

- 还没有用真实视觉模型跑过 6 套方案。需要确认的问题：
  - 模型能否在一次回答里写完 6 套方案；
  - 方向选择是否贴合画面；
  - 合并损坏检查的误报率。
- 6 套方案的渲染时间约为三套的两倍（3 个并行）。
- 本地光晕、蒙版边缘的像素检查，以及「再来几套」，都还没有做。
