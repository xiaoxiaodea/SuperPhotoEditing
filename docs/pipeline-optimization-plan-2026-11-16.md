# 后期流程优化规划

日期：2026-11-16。本文先说明成片为什么不尽人意，再给出新的流程设计和分阶段实施计划。结论来自三类证据：最近一批真实任务的配方与审计、管线源码、以及今天在本机用 LightCraft 做的一次对照实渲。本文只是规划，生产代码没有改动。

## 一、结论

成片不好，不是某个参数没调对，而是流程本身只会"防止修坏"，不会"把图修好"。具体有四个缺口，按影响排序：

1. **没有人在看图。** 最近所有实测都跑在 `vision_provider: local`，诊断只来自直方图。系统不知道画面里有人、脸在帽檐阴影里、天空有灰尘。
2. **改动被层层限幅压到看不见。** 同一张照片，LightCraft 自带的 Auto 给出对比 +68、高光 −66、阴影 +52；管线最终交付的是对比 +13、高光 −13、阴影 0。
3. **没有任何局部调整。** 最近 30 张交付的 `masks` 全是空的。专业后期的大部分工作量在局部（压天空、提主体、补脸、引导视线），这部分现在是零。
4. **验收只有"没损伤"，没有"变好了"。** 像素质检对任何安全输出都给 100 分，原片与自己比较也是 100 分。所有修复路径都只会减弱（65% → 35% → 撤销），没有一条路径会加强。

这四点在 9 月的两篇诊断里已经出现过（"交付条件不要求有明确的审美改善""最主要的剩余问题是审美判断"）。之后的工作主要是继续增加保护规则和测试（现在 611 项），方向需要调整：**先补能力，再谈保护。**

好消息是引擎不是瓶颈。今天用同一个 LightCraft、同一张 JPEG，看图后手写一份带 4 个局部蒙版的参数，单次渲染 1.3 秒，结果明显比当前交付完整（见第三节）。

## 三、今天的对照实渲

目的：确认"引擎够用，问题在规划和限幅"。同一张 `DSC_2121` 原片副本，LightCraft v0.21.1，长边 1600。

| 版本 | 做法 | 观察 |
| --- | --- | --- |
| 1 原片基线 | 不加任何设置 | 整体偏暗发灰，脸在帽檐阴影里，天空发白 |
| 2 当前管线交付 A | 现有流程 | 相当于全局提亮半档；天空更白，脸仍暗 |
| 3 LightCraft Auto | `develop.auto` | 云层细节出来了，但整体偏暗偏平 |
| 4 看图后手写 | 全局基础 + S 曲线 + 4 个蒙版（天空线性渐变、人物径向、脸部径向、前景线性渐变） | 天空有密度，湖水颜色更饱满，脸部提亮并回暖，外套褶皱保留 |

产物在 `.task-cache/pipeline-plan-probe-2026-11-16/`：`compare.jpg`（四宫格）、`compare_crop.jpg`（人物局部）、`directed-develop.json`（第 4 版的完整参数）。

第 4 版是一次写成、没有迭代的草稿，不是终稿：天空蓝得略重，远山的雾还可以再处理。它要说明的只是同一引擎、同一 JPEG 能到的位置比当前交付远得多。

这次实渲还暴露了三个需要写进计划的事实：

- **加强天空会让传感器灰尘更显眼。** `spot.findDust` 找到 58 处候选，其中 40 处落在山体带（多半是误报），左上角那条明显的长条灰尘反而没修掉（`compare_dust.jpg`）。灰尘修复必须由看图的模型给坐标，不能只靠自动检测。
- **预设不能直接整套盖上去。** 把 `#LC - CINE V1.xmp` 原生应用到这张偏暗的 JPEG，天空和山很有电影感，但脸和湖水全黑（`out_xmp_cine_v1.jpg`）。风格必须叠在已校正的基础之上，并配合主体保护。
- **单次渲染只要 1 秒左右。** 现在一张图要等好几分钟，时间花在阶段导出和重试上，不在引擎上。

## 四、目标与验收

不再用"技术分 100""独立方向数"当指标。改用一套固定评测集加盲评：

- **评测集**：30 张，覆盖现有 10 张新疆片，再补人像、夜景、室内、城市、逆光、美食等。有 RAW 就加几张 RAW。
- **盲评**：每张并排给出匿名的若干版本（原片、Auto、旧管线、新管线），你点选最好的一张，约 10 分钟。
- **验收线**：
  - 新管线成片胜过原片的比例 ≥ 80%；
  - "看不出区别"的比例 ≤ 10%；
  - 新管线胜过 LightCraft Auto 的比例 ≥ 65%（一个自动后期系统至少应该赢过引擎的一键自动）；
  - 确认的损伤（偏色、裁切、光晕）≤ 5%；
  - 单张任务 ≤ 2 分钟。

先用旧管线跑一遍，得到起点数字。之后每个阶段完成都重跑同一套。

## 五、新流程

```
原片
 └─ 基线渲染（1 次）＋ 现有测量
     └─ ① 读图：场景、主体框、区域清单、问题清单（按严重度）、灰尘坐标
         └─ ② 修图方案 EditPlan：全局基础 ＋ 区域蒙版 ＋ 配色，每项写明目的
             └─ ③ 编译：EditPlan → LightCraft 原生 develop JSON（确定性，带范围校验）
                 └─ ④ 渲染（每候选 1 次）
                     └─ ⑤ 看图复核：逐条目的是否达成、有没有损伤 → 给出加或减的具体修正
                         └─ ④⑤ 循环，最多 3 轮
                             └─ ⑥ 硬性安全门（现有像素质检）：失败则带着原因回到 ② 重新规划
                                 └─ ⑦ 交付 A / B / C ＋ 记录反馈
```

和现有流程的五处根本区别：

1. **每一步都有模型在看真实渲染结果**，不再靠直方图推断。
2. **修正是双向的。** 复核可以说"脸再亮 0.3 档"，不只是"减弱到 65%"。
3. **安全门失败时重新规划，而不是把方案缩到零。** 例如"提亮导致天空过曝"的正确处理是加一个天空蒙版压回去，而不是取消提亮。
4. **强度由看图决定，不由文件类型决定。** JPEG 的余量按实测（高光裁切、暗部噪声、天空色带风险）给，不再一刀切。
5. **一个候选只渲染一次**，出了问题再做定位（去掉某组控制重渲，1 秒一次）。

A / B / C 重新定义为：**A 自然完成版**（基础 + 局部，颜色忠实）、**B 同一意图的更强版**（光比和密度更足）、**C 一个风格化版**（原生预设叠在 A 的基础与蒙版上）。不再以 Lab 距离为目标去"制造差异"；太接近时如实告知即可。

"谁来看图"有两种接法，共用同一套编译、渲染和安全门：

- **服务内置**：通过现有 OpenAI 兼容接口接一个一线多模态模型，网页界面和目录批量导入都能用。
- **助手直驱**：`skills/superphoto` 现在只让助手调用 `edit` 然后看成片。可以再给它 `baseline`、`render <plan.json>` 两个底层命令，让调用它的助手自己读图、写方案、看结果。今天的实渲就是这种模式，不需要额外的密钥。

## 六、分阶段实施

人日是粗估，按一个人专注做来算。

### P0 评测基准（1–2 天）

- 选定 30 张评测集，清单写进 `scripts/bench_manifest.json`。
- 新增 `scripts/bench.py`：批量跑，每张输出原片基线、Auto、当前管线、新管线四个版本。
- 复用 `.task-cache/xinjiang-review-template.html` 做匿名盲评页，结果存 `bench-results.json`。
- 用旧管线跑一遍留底。

验收：你完成一次盲评，得到旧管线的四个起点数字。

### P1 接上视觉模型（1–2 天）

- 建 `.env`，走现有 `openai` 通道接一个强多模态模型。先在评测集里挑 5 张比较读图能力（主体框准不准、有没有发现暗脸和灰尘、偏色判断对不对），再定型号。建议第一候选用 Claude 当前的 Sonnet 或 Opus 档，今天的读图和手写参数就是同一类模型完成的。
- 本地模型只作降级：9 月的校准记录显示 32B 的本地模型审片都不可靠，12GB 显存能跑的更小。
- `vision_provider=auto` 静默降级改成显式提示：没有视觉模型时，界面和命令行明确写"仅基础校正"，不再假装给出三套方向。
- 只上传 1280px 预览（现状已如此）。加一个开关控制人像是否允许上传。
- 同步做助手直驱：`agent.py` 增加 `baseline`、`render` 两个命令，更新 `SKILL.md`。

验收：评测集每张的 `critique.json` 都有主体框、区域清单和按严重度排序的问题；`DSC_2121` 被识别为环境人像且指出脸部偏暗。

### P2 松绑限幅，改为单次渲染（2–3 天）

- 新增 `editplan.py`（结构化方案）和 `plan_compile.py`（直接编译成 LightCraft 原生 JSON，不再经过 Adobe 键名中转）。旧路径用 `SUPERPHOTO_PIPELINE=legacy` 保留，便于对照。
- 把"JPEG 一律保守"换成"按余量给范围"。初始建议范围：曝光 ±1.0EV、阴影 ≤ +60、高光 ≥ −80、对比 ±40、去雾 ≤ +35、清晰度 ≤ +30，由复核和安全门兜底。
- 删除 `_protect_sky` 的曝光上限，换成"需要提亮且天空偏亮时，自动加天空蒙版压回"。
- 基础修图不再乘 `lut_amount`；强度系数只作用于风格层。
- 改写 `critique.py:289` 一段，目标从"保守"改为"一眼可见、完成度高、不留损伤"，并给出典型幅度。
- 6 阶段导出改成 1 次渲染加最终检查；安全门失败时才做分组定位。
- 没有视觉模型时的兜底：`develop.auto` 的结果按 0.6 混合进基础，保证本地模式也有可见改善。
- 停掉每次任务都跑的 NumPy 预览渲染和它的评分（LightCraft 可用时）。

验收：盲评"看不出区别" ≤ 25%，胜原片 ≥ 60%，单张 ≤ 2 分钟。这一步只有全局调整，预期提升明显但还不够。

### P3 局部调整（3–4 天）

这是最大的质量杠杆。

- `EditPlan` 的蒙版类型：`linear`（天空、前景渐变）、`radial`（主体、脸、光区）、`luminance_range`（只动暗部或亮部）、`color_range`（水面、植被，按取样点）、引擎的 `subject / sky / background`，以及加减交组合（例如天空 = 线性渐变 ∩ 亮度范围 − 主体径向）。这些 LightCraft 都已支持，前四种不需要 AI 模型。
- 视觉模型输出归一化的框、点和地平线位置，由编译层换算成蒙版几何。径向蒙版配大羽化，能容忍坐标误差。
- 建一套标准动作模板，按区域参数化：天空压暗增密、主体提亮、脸部补光回暖、前景压暗引导、远景分层去雾、水面增色、背景降饱和、暗角。
- 蒙版验证：同一参数带蒙版和不带蒙版各渲一次，取差异图，检查覆盖范围是否落在目标框内（11-14 已做过同类探测）。
- 灰尘：视觉模型给坐标，用 `spot.add mode=heal`；`spot.findDust` 只在天空区域内采纳。
- 把裁切和拉直接回主流程（9 月诊断指出 art-direction 分支跳过了裁切）；水平线用 `crop.autoStraighten`。
- 可选：安装 SAM 3（约 3.4GB，Meta SAM License），用 `object` 点选或 `prompt` 文本得到精确的人物和脸部选区。需要你确认许可。

验收：评测集中有人物的照片，脸部亮度相对原片有可测提升且无光晕；有天空的照片天空密度提升；盲评胜原片 ≥ 75%。

### P4 看图闭环与可靠审片（3–4 天）

- 复核输入用单张画布：原片与成片并排，加脸、天空、暗部的 100% 局部裁切。9 月校准已经证明多图输入会混淆对应关系，单画布可靠。
- 复核按方案逐条回答"目的达成、部分达成、未达成"，列出损伤及其区域，输出具体修正量。
- 沿用 `pair_review.py` 的可靠性协议：左右互换各判一次、相同图片直接跳过。
- 停止条件：目的都达成且无损伤，或满 3 轮。每轮与上一轮比较，只保留更好的。
- 最低改善门：诊断有中等以上问题、成片却被判"无可见改善"时，重新规划一次；原片确实已经完整时，如实告知"此片改动空间小"。
- 用你在 P0 的盲评结果校准审片模型。一致率到 75% 之前，模型只做目的检查和损伤检查，选片仍由你来。

验收：达到第四节的全部验收线。

### P5 风格层重做（3–5 天）

- 用 LightCraft 原生方式导入 LeoCarbin 预设（`preset.import`，或 `render --settings x.xmp`），保留校准、全局色轮和曲线。
- 给每个预设建一张"性格卡"：在它自带的 DNG 样片上渲染前后对照，让视觉模型一次性写下影调、配色、适用场景和禁忌，存成 `preset_cards.json`。
- 选风格的方式改成"试了再看"：对当前照片渲染 6–8 个候选预设的小图拼成一张，让视觉模型看图挑，不再用直方图匹配题材。每张小图约 1 秒。
- 应用顺序：先做曝光归一和基础校正，再按 40–100% 叠预设（排除它的曝光和白平衡），最后重新应用主体保护蒙版，再过一遍复核。
- 预设仍只留在本地，不进 wheel。

验收：C 位在盲评中被选为"最喜欢"的比例 ≥ 20%，且无主体被压黑、白色被染色的损伤。

### P6 输入输出与反馈（1–2 天，可并行）

- 以后尽量拍 RAW 或 RAW+JPEG；流程在同名 RAW 存在时优先用 RAW。JPEG 的高光无法恢复，天空推得重会出色带。
- 导出增加原尺寸选项，质量 95，`sharpen=screen`；高感 RAW 用 `enhance.denoise`。
- 下载镜头数据库（`lens.downloadDatabase`）。
- 反馈不只记"喜欢哪种预设"，还记强度倾向（例如多次说"亮一点"则提高默认亮度先验）。
- 你提供 5–10 张自己认为修得好的成片，由视觉模型总结成一张口味卡，放进规划提示。

### 之后：清理

新管线在评测集上稳定胜出后，退役旧路径里的限幅和阶段回退代码，测试集随之精简，只保留硬性安全门相关的部分。611 项测试里有相当一部分是在固化"保守"行为，届时需要改写而不是让它们阻止改动。

## 七、本周可以先做的三件事

按投入产出比：

1. **接上视觉模型**（P1）。只需要 `.env`，不改代码。现有的读图提示、蒙版规划、成片复核会立刻开始工作。
2. **放开限幅**（P2 的一部分）。改 `preference.py` 的四个函数和 `critique.py` 的一段提示，约一天，含测试调整。
3. **输出线性和径向蒙版**（P3 的一部分）。`lightcraft.py:_mask_document` 支持新的 `kind`，从主体框生成径向蒙版、从天空判断生成线性渐变，一到两天。

这三件做完，再跑一次评测集，就能知道后面几个阶段的优先级要不要调。

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 放开强度后，光晕、色带、偏色会变多 | 复核循环加现有安全门；A 位始终保持自然；初期多看评测集 |
| 视觉模型给的坐标不准 | 径向蒙版大羽化；差异图验证覆盖；需要精确边缘时用 SAM 3 |
| 审片模型判断不稳 | 单画布、左右互换、与你的盲评校准；达标前不让它自动选片 |
| 云端调用的费用、时延和隐私 | 只传预览图；每张约 8–11 次调用；人像上传设开关；保留本地兜底 |
| 加强天空后灰尘更显眼 | 灰尘修复排在天空处理之前，作为 P3 的必做项 |
| 预设整套应用会压黑主体 | 先归一再叠加，排除曝光和白平衡，叠后重新做主体保护 |

## 九、需要你决定的事

1. 是否同意把 1280px 预览发给云端视觉模型？用哪一家？人像片是否也可以上传？
2. 是否下载 SAM 3（约 3.4GB，Meta SAM License）？
3. 以后是否拍 RAW 或 RAW+JPEG？
4. 你想要的方向偏"自然通透"还是"明显风格化"？能否给 5–10 张你认为修得好的参考图？
5. 是否愿意花约 10 分钟做一次评测集盲评？

前两项不影响 P0 和 P2 开工。
