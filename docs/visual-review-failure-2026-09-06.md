# 视觉复核误判与单个候选拖垮交付

## 两个实际失败

`8b60fbd6-241c-42f6-bd21-637c2ff10437`：城市与水面反光照片。原片中反光已呈橙暖色，诊断却写入“水面反光的冷色调”。B 的四轮实际导出都通过像素检查，但复核不断引用这条错误描述，认定冷反光变暖，并将 B 失败升级为整单失败；C 没有执行。

此前的确认步骤会把第一轮的指控直接送给同一个模型，即使换了图像顺序，仍可能重复错误判断。确认步骤也未保存独立观察依据。

`903607b7-4b45-4d31-94d2-6ba1c3bb6206`：游船与金色倒影的近景，没有可见天空。计划要求创建天空蒙版；Lightroom 未创建新蒙版，原先代码等待后抛异常，整单退出。

## 修复行为

- 诊断和规划区分环境色与反射光，明确不能把全图冷色套到局部高光，不应给无天空的照片添加天空蒙版。
- 复核将自动保护文字视为待核实的描述，以原片实际像素为准。相同渲染直接记录 same，不让模型凭空报告新增损坏。
- 第二次检查不带入第一次的指控及错误保护文字。重新观察两张图，保存 `reference_observation`、`result_observation`、`evidence` 和损坏类型；观察缺失、类型不一致或未确认，都不授权撤销。第一轮的意见仍如实保留。
- 真实损坏的修复使用新原片副本，优先移除相关颜色、细节或影调控制。例如色偏修复真正撤掉共享的白平衡偏移，避免 A/B 都偏暖、混合后仍偏暖的无效重试。
- 候选失败时保存每轮记录并撤下该候选，继续完成其余候选。API 和前端按实际通过数量交付，撤下的候选不能提交为反馈选择。全部候选失败时仍明确报错。
- 对无新蒙版的情况，插件返回结构化跳过结果；现有蒙版和原有滑杆保持不变。执行器记录被跳过目标并移除对应有效配方，保留其他已完成蒙版。其他 SDK 写入或回读异常继续作为失败记录。

## 验证

- Python 全套 157 项通过，包含错误保护描述不进入独立复核、相同图片不可能新增损坏、真实色偏控制撤销、无天空保留主体蒙版、单个候选失败继续完成 C、全部不合格不交付，以及 API 不暴露撤下的选项。
- Lua 原生蒙版契约和连接唤醒契约检查通过；前端语法检查通过。实际前端函数的 DOM 检查覆盖 A/C、仅 C、完整 A/B/C 的数量、默认选择、原片比较和撤下选项不可选。
- 对同一份原始失败 B 导出重新运行本机模型：独立观察正确描述原片的金色反光，认为成片仍是相同金色，没有确认新增损坏。完整记录：`.task-cache/water-reflection-review-recheck.json`。第一轮仍有负面意见，保留在审计中；这不等于证明审美改善。
